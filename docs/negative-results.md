# 负结果册

端侧选型里最贵的信息是"这条路不通"，而它恰好最不容易留下来：失败只发生一次，事后只剩"试过，不行"这句对外人等于零的话。
所以这里记的是**可以复核的失败**：假设是什么、得到什么结果、因此判为什么、证据在哪。

判定只有三种：`放弃`（此路不通）/ `改法`（换判据后成立）/ `未解`（知道错但没解决）。

---

## N-01 把功耗做成第三维 —— 放弃

- **假设**：能耗是端侧选型的一等约束，应该进矩阵。
- **结果**：Windows 读不到 RAPL，物理功耗需外接功率计；代理指标（HWiNFO package power / `powercfg` 电池放电 / CPU 时间 × 占用）**跨机型不可比**，噪声撑不起一张图。
- **判定**：`放弃`。且是"宁可少一维"的放弃——放进去会让人以为我们测过，这比缺一维更糟。
- **证据**：`docs/research-plan.md` §6。

## N-02 中文候选名用编辑距离查撞车 —— 改法

- **假设**：Levenshtein 距离能识别"打错就串"的高风险名字对。
- **结果**：英文侧有效；中文侧标出的 20 组里绝大多数无意义——**两字中文词的编辑距离恒为 2**，判据退化成"只要不等就危险"。
- **判定**：`改法`。中文改用**共用字检测 + 词形**，英文仍走编辑距离；改后只剩 3 组真风险。
- **证据**：`tools/name_cluster.py` 的 `form_sim()` 与风险判定分支。

## N-03 契约凭记忆写，编出一个不存在的枚举值 —— 改法

- **假设**：`/transcript.json` 的 `kind` 有 `asr` 这个值。
- **结果**：真实后端只发 `final` / `trans`。`tools/contract_check.js` 19 项检查里有一项一开始是对着错文档写的。
- **判定**：`改法`。契约必须以**一次真实响应**为准，检查脚本不能从文档反推。
- **证据**：`docs/contract.md`、`tools/contract_check.js`。

## N-04 扩展 ID 在 unpacked 下无法稳定 —— 未解

- **假设**：同一份代码，加载路径变了 ID 也不变。
- **结果**：实测同一份代码，从主项目 `extension/` 加载得 `ajgmcdhh…`，从本仓库加载得 `hbfbckcfmnnakaekleoadicgnghofcij`。unpacked 的 ID 由**路径**派生，只有商店安装或 manifest 写死 `key` 才能固定。
- **判定**：`未解`。当前不阻塞（后端 CORS 不绑 ID），但 Native Messaging 的 `allowed_origins` 必须写死 ID → 做 NM 前先定 ID 策略。
- **证据**：`README.md` §已知限制。

## N-05 用扩展抓桌面客户端的系统声音 —— 放弃（原理上不可能）

- **假设**：`tabCapture` 能覆盖"用户听到的所有声音"。
- **结果**：只能抓**标签页**。Zoom / 腾讯会议的桌面客户端不是标签页；要抓全系统声音必须走 WASAPI loopback（由后端做）。
- **判定**：`放弃`。这条直接决定产品形态必须是"扩展 + 本机引擎"两件套，而不是纯扩展。
- **证据**：`README.md` §明确的边界。

## N-06 让扩展自带推理引擎 —— 放弃（平台不允许）

- **假设**：商店里发一个自带引擎的扩展，用户装完即用。
- **结果**：MV3 service worker 不是常驻进程、没有 `child_process`；商店政策也禁止包内捆绑原生可执行文件。
- **判定**：`放弃`，安装方向反转：**桌面安装包带引擎，装完提示去装扩展**，而不是扩展带引擎。
- **证据**：`docs/distribution.md`。

## N-07 界面 i18n 提前抽 —— 放弃（暂时）

- **假设**：早点抽 i18n，出海更顺。
- **结果**：真机验收脚本里有中文文案断言，抽 i18n 会打断它们；现阶段用户全是中文用户。
- **判定**：`放弃`（暂时）。等真有非中文用户再抽。
- **证据**：`README.md` §明确的边界。

## N-08 运行时从 ONNX 换成 ncnn —— 净收益为负

- **假设**：甩掉约 45 MB 的 ONNX Runtime 值得换运行时。
- **结果**：ncnn 的真实收益只有两项——去掉 ORT 依赖（约 45 MB）、模型压缩包更小（zh-14M：22.2 MB vs 70.6 MB）。
  但 96 MB Lite 档用 onnx 已能达成，所以它省的是**安装包里的 45 MB，不是能力**；
  代价是放弃 Windows on ARM（`sherpa-ncnn 2.1.15` 无 `win_arm64` 轮子）并重做导出与验证。
- **判定**：`放弃`。主线留 ONNX，接受多背 45 MB。
- **重新评估触发条件**（两条同时满足）：P1 打出的 onedir 总体积 > 200 MB，且确认不需要 Windows on ARM。
- **证据**：`docs/adr-001-runtime.md`。

## N-09 两个候选名撞车 —— 放弃

- **`pitalk`**：四处撞车，其中一个是跑在树莓派 Zero 2 W 上的 P2P 语音通话器——正是我们想蹭的那个联想。
- **`offtalk`**：域名已被注册（`offtalk.com` 停在 HugeDomains 停放页，标价 $6,095）。
- **判定**：`放弃`。改用 `Offlisten` + 中文名 `录匣`，`listen anything` 降级为标语而非产品名。
- **证据**：`docs/naming.md`；Verisign RDAP 查询（`offlisten.com` / `.net` 404 = 未注册）。
