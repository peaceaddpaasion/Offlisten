# 负结果册

> 这里只记**没成的事**，以及为什么没成。
> 阳性结果会自己出现在 README、图和简历里；阴性的如果不写，就只剩下"我们试过，不行"这句话，
> 而这句话对外人等于零——它既不能阻止别人重踩，也不能证明我们真的试过。

## 记账规则

1. **每条必须有证据路径**（文件、命令输出、commit、memory 日期），没有证据的不许进册。
2. **判定只有三种**：`放弃`（此路不通）/ `改法`（换判据后成立）/ `未解`（知道错但没解决）。
3. **禁止形容词**。"效果不好"、"不太行"、"有坑" 一律驳回，必须写成可复核的句子。
4. **推翻自己的结论要写在最前面**，不许悄悄改图了事。

## N-01 「12 格里只有 1 格能用」——这条主结论是错的（2026-11-12）

- **假设**：四条约束（CPU 可跑 / 流式 / 可分发给未知用户 / 模型不降级）下，只有 `sherpa-onnx × x86-64 CPU` 一格成立。
- **做法**：画矩阵 → 复核每一格的外部依据时，回头查了 `sherpa-ncnn` 的 release 页。
- **结果**：release tag `asr-models`（2025-09-13）下有 6 个 asset，全是 SenseVoice 的 ncnn 模型包
  （`sherpa-ncnn-sense-voice-zh-en-ja-ko-yue-2024-07-17` 与 `-2025-09-09`，各含默认 / int8 / float32）；
  官方文档也有 SenseVoice 专章，含「Real-time speech recognition from a microphone」。
  → **"ncnn 没有更强的模型可换"这个前提不成立。**
- **判定**：`改法`。主结论改为「2 格通过三条硬约束，其中 1 格有实测」，并把 ncnn 那格从 `limited` 上调为 `ok · 运行时未测`。
- **为什么值得单列**：这是一条**对我们有利的错误**——把竞品判死，自家路径就显得唯一。
  这类错误最不容易被自查，因为改它等于给自己减分。
- **证据**：`docs/bench/matrix.svg` v1 vs v2、`docs/bench/README.md` 修订记录、GitHub API `repos/k2-fsa/sherpa-ncnn/releases`。

## N-02 「测过」这个词把所有东西粘在了一起（2026-11-12）

- **触发**：用户质疑「ncnn 试验过，有实测啊」。第一版修正稿把它写成"完全没测"，也不对。
- **做法**：逐项核对三条证据——本机是否装过、代码是否引用、报告里的数字是不是估算。
- **结果**：
  - `.venv` 与系统 Python **均无 `sherpa_ncnn`**；全仓 `.py` **无 `import sherpa_ncnn`** → Windows 运行时从未跑过；
  - `ASR升级评估报告.md` §3 自己标着「⚠️ RTF 为基于公开 benchmark 的**估算值**……落锤前按附录命令实测」→ 那些 `0.3~0.6` 是估算；
  - 但 2026-10-25 记录「en-patched APK 卸载原版后安装成功」，且换过 `zipformer-libri-giga-70M` → **ncnn 在 Android 真机上真的跑过**。
- **判定**：`改法`。证据分级从"跑过 / 没跑过"两级，改成 `L1 官方 / L2 运行时实测 / L2′ 只测模型侧 / L3 推断` 四级；
  并承认**图缺一列 Android arm64**，而那一列恰是唯一有真机数据的地方。
- **教训**：「测过」必须带宾语——测过**什么**（模型取证？运行时？在**哪台机器**上？）。缺任何一个限定，这个词就是噪声。
- **证据**：`pip show sherpa-ncnn`（无输出）、`grep -rn "import sherpa_ncnn" --include=*.py`（无匹配）、`docs/bench/README.md` §证据分级。

## N-03 功耗作为第三维：砍掉（2026-11-12）

- **假设**：能耗是端侧选型的一等约束，应该进图。
- **做法**：评估可测量性。
- **结果**：Windows 读不到 RAPL；物理功耗需外接功率计；代理指标（HWiNFO package power / `powercfg` 电池放电 / CPU 时间 × 占用）**跨机型不可比**，噪声大到撑不起一张图。
- **判定**：`放弃`。并且是"宁可少一维"的放弃——**放进去会让人以为我们测过**，这比缺一维更糟。
- **证据**：`docs/research-plan.md` §6。

## N-04 中文候选名用编辑距离查撞车，判据失效（2026-11-12）

- **假设**：Levenshtein 距离能识别"打错就串"的高风险名字对。
- **做法**：`scripts/name_cluster.py` 对 21 组候选跑英文编辑距离 + 中文编辑距离。
- **结果**：英文侧有效；中文侧标出的 20 组里绝大多数无意义——**两字中文词的编辑距离恒为 2**，
  判据退化成"只要不等就危险"。改用**共用字检测**后，只剩 3 组真风险。
- **判定**：`改法`。中文走共用字 + 词形，英文走编辑距离。
- **证据**：`scripts/name_cluster.py` 的 `form_sim()` / 风险判定分支。

## N-05 ncnn 换线的净收益为负（2026-11-06 决议，2026-11-12 部分推翻）

- **假设**：甩掉约 45 MB 的 ONNX Runtime，值得把运行时换到 ncnn。
- **做法**：评估质量天花板、平台覆盖、收益边界、迁移成本四项。
- **结果**：四条理由里，**第 1 条（无更强模型）已被 N-01 推翻**；剩余三条仍成立——
  ① `sherpa-ncnn 2.1.15` 无 `win_arm64` wheel（`sherpa-onnx 2.0.1` 有）；② 96 MB Lite 档用 onnx 已能达成，ncnn 省的是安装包里的 45 MB，不是能力；③ 迁移要重导重验，成本不低。
- **判定**：`改法`。决议（主线留在 ONNX）不变，但**理由从 4 条减为 3 条**，且必须注明"质量天花板"这条作废。
- **为什么留着**：一条决议如果靠一条错误理由撑着，下次有人拿新证据推翻那条理由时，会连带以为整个决议也塌了。**把作废的理由标出来，决议才站得稳。**
- **证据**：`docs/adr-001-runtime.md`、`docs/tech-notes.md` §1.4。

## N-06 契约凭记忆写，写出了一个不存在的枚举值（2026-11-12）

- **假设**：`/transcript.json` 的 `kind` 有 `asr` 这个值。
- **做法**：按记忆写 `docs/contract.md`，再写 `scripts/contract_check.js` 去对运行中的后端。
- **结果**：真实后端只发 `final` / `trans`，`asr` 不存在。19 项检查里有 1 项一开始是我编的。
- **判定**：`改法`。契约必须以一次真实响应为准，检查脚本不能从文档反推。
- **教训**：**文档凭记忆写=伪造证据**，哪怕细节只错一个字符串。

## N-07 扩展 ID 在 unpacked 下无法稳定（未解）

- **假设**：同一份代码，加载路径变了 ID 也不变。
- **结果**：实测同一份代码，从主项目 `extension/` 加载得 `ajgmcdhh…`，从本仓库加载得 `hbfbckcfmnnakaekleoadicgnghofcij`。
  unpacked 的 ID 由**路径**派生，只有商店安装或 manifest 里写死 `key` 才能固定。
- **判定**：`未解`。当前不阻塞（后端 CORS 不绑 ID），但 Native Messaging 的 `allowed_origins` 必须写死 ID → 做 NM 之前必须先定 ID 策略。
- **证据**：`README.md` §已知限制。

## N-08 用扩展抓桌面客户端的系统声音：原理上不可能

- **假设**：`tabCapture` 能覆盖"用户听到的所有声音"。
- **结果**：只能抓**标签页**。Zoom / 腾讯会议的桌面客户端不是标签页，抓不到；要抓全系统声音必须走 WASAPI loopback（后端做）。
- **判定**：`放弃`。这条直接决定了产品形态必须是"扩展 + 本机引擎"两件套，而不是纯扩展。
- **证据**：`README.md` §明确的边界。

## N-09 商店不允许包内捆绑原生可执行文件 → 安装方向要反过来

- **假设**：扩展商店里发一个自带推理引擎的包，用户装完即用。
- **结果**：MV3 service worker 不是常驻进程、没有 `child_process`；商店政策也禁止捆绑原生可执行文件。
- **判定**：`改法`。安装方向反转：**桌面安装包带引擎，装完提示去装扩展**，而不是扩展带引擎。
- **证据**：`docs/distribution.md`。

## N-10 界面 i18n：收益为零，且会打断验收

- **假设**：早点抽 i18n，出海更顺。
- **结果**：当前真机验收脚本里有中文文案断言，抽 i18n 会打断它们；而现阶段用户全是中文用户。
- **判定**：`放弃`（暂时）。等真有非中文用户再抽。
- **证据**：`README.md` §明确的边界。

## N-11 两个候选名撞车（命名否决记录）

- **`pitalk`**：四处撞车，其中一个是跑在树莓派 Zero 2 W 上的 P2P 语音通话器——正是我们想蹭的那个联想。
- **`offtalk`**：已被注册占用（`offtalk.com` 停在 HugeDomains，标价 $6,095，是停放页不是产品）。
- **判定**：`放弃`。改用 `Offlisten` + 中文名 `录匣`，并把 `listen anything` 降级为标语而非产品名。
- **证据**：`docs/naming.md`、Verisign RDAP 查询（`offlisten.com` / `.net` 404 = 未注册）。

## 这份册子本身的方法论

阴性结果的稀缺不是因为失败少，是因为**失败不被记录**。它有三个特性让它天生难以留存：

| 特性 | 后果 | 对策（本册的做法） |
|---|---|---|
| 只发生一次 | 错过就永久丢失 | 当场写，日期 + 证据路径一起写 |
| 对我们不利 | 没人主动记 | 强制"推翻自己的结论写在最前面" |
| 没有格式 | 变成"试过不行"这种废话 | 固定四段：假设 / 做法 / 结果 / 判定 |

最后一条最重要：**"试过不行"不是信息，"在什么假设下、用什么做法、得到什么可复核的结果、因此判定为哪种失败"才是信息。**
前者只能证明我们累过，后者能替别人省一次。
