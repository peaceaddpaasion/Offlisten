# 命名与定位（2026-11-12）

> 本文只写**实测过的事实**和**据此得出的判断**。标「未查」的一律没有结论，不要当结论用。

## 0. 一句话

体积还有一大截可砍的空间，你以为的「70MB 英语 + SenseVoice」其实是两条不同的管线；
名字方面 **pitalk 已经死了**，**listen anything 只能当定位句、不能当名字**——因为它搜不到你。

---

## 1. 先纠正技术前提（这条直接决定体积方案）

你的原话是「70m英语和moe是 SenseVoice / zipformer」。实测这两者不是一回事：

| 引擎 | 模型 | int8 体积 | 形态 | 语言 |
|---|---|---|---|---|
| `sensevoice`（**当前默认**） | SenseVoice `model.int8.onnx` | **228.2 MB** | 非流式，出标点 | zh / en / ja / ko / yue |
| `zipformer`（英文低延迟档） | zipformer-en-2023-06-26 int8 encoder | **66.9 MB**（整模型 ≈ 70MB） | **流式**，边说边出字 | en only |
| （新增候选） | zipformer-zh-14M-2023-02-23 int8 三件套 | **25.3 MB**（enc 21.6 + dec 1.89 + join 1.8） | 流式 | zh only |

代码实证：`pc_transcriber.py:1178` 按 `--engine` 二选一建识别器，默认 `sensevoice`（第 1303 行）；
`build_recognizer()` 走 zipformer 在线识别器，`build_offline_sv()` 走 SenseVoice 离线识别器。

**结论：**

- 「70MB 英语包」成立，但它**只是英文流式档**，不含中文。
- 你要的中文，如果走 SenseVoice 就是 **228MB**；想压到 25MB 只能上 14M 小模型。
- SenseVoice 一个模型通吃 5 种语言，这本身就是「i18n 免费」——**它比「英文包 + 中文包」两套更省事，只是一次性占 228MB**。

所以体积不是「英语 70 + 中文 X」，而是**三档可选的模型包**：

| 档位 | 组成 | 体积 | 适合谁 | 代价 |
|---|---|---|---|---|
| **Lite 轻装** | zipformer-en 70MB + zh-14M 25MB + VAD 1MB | **≈ 96 MB** | 老机器 / 想秒装 / 只要中英 | 14M 中文对术语、口音、远场会掉字；无标点 |
| **Standard 标准（= 现状）** | SenseVoice int8 228MB + VAD 1MB | **≈ 229 MB** | 会议、课堂、多语言 | 非流式，延迟高于 zipformer |
| **+ 翻译（可选下载）** | Argos 单语言对 | **+166 MB / 对** | 真要中英互译 | torch 等运行时另计约 660MB |

**不要发 fp32**：`model.onnx` 895MB 和 `sense-voice.tar.bz2` 999MB、`en-streaming.tar.bz2` 296MB 都是开发期产物。
**翻译必须按语言对单独下**，否则 229MB 直接变 1.2GB。

## 2. 名字：三个候选，两个已经可以判死

### 2.1 pitalk —— 死，四撞，而且撞得最狠

| 冲突方 | 是什么 | 严重度 |
|---|---|---|
| `github.com/assaft/pitalk` | **跑在 Raspberry Pi Zero 2 W 上的 P2P 语音消息系统** | **致命**：同硬件、同语音、同语义 |
| `github.com/swairshah/PiTalk` | macOS 菜单栏本地语音中枢，8 个 release | 高：同为「本地语音」工具 |
| Google Play「피톡 PiTalk」 | 韩国交友聊天 app，10 万+ 下载 | 高：同名 app 占位 |
| PikiTalk | Web3 即时通讯 | 中 |

你想借「树莓派」的联想，但**已经有一个叫 PiTalk 的东西在树莓派上做语音**。
这名字一上线，搜索前三位全是别人，你的「搜索指数发力」直接失效。

### 2.2 offtalk —— 产品没撞，但 .com 已被注册

- 搜索 `"OffTalk"`：返回的是 **Offtrack**（AI DJ）、**officetalk**、**OAtalk** —— **没有同名产品**，品牌冲突低。
- 域名 RDAP 实测（Verisign）：`offtalk.com` → **HTTP 200，已注册**；`pitalk.com` → 200 已注册；`listentalk.com` → 200 已注册。
- `.app` 的 RDAP 查询在本机网络被拦（http=000），**没查到就不下结论**。

判断：「OffTalk」可用性中等——**词好（离线 + 说），但主域要买**。如果买不到 .com，用 `offtalk.app`（若空）或 `getofftalk.com` 会弱一档。

### 2.3 listen anything —— 当名字是最差的，当定位句是最好的

这条要直说，因为它和你的目标直接冲突：

- 它是一个**通用动词短语**，全网有几百万条同义内容（播客、课程、歌词）。
- 搜「listen anything」永远搜不到你；你的品牌词会被通用词**稀释到零**。
- 而你要的恰恰是「搜索指数发力」——**通用短语是最不利于建立搜索资产的名字类型**。

**但**作为一句话定位，它是最强的，因为它准确表达了差异化：全天候、全来源、自由。
正确用法：

```
名字：〔品牌词〕
品类：本地离线会议转写
定位句：Listen anything. 拔掉网线也能用。
```

### 2.4 聪明豆 —— 当玩笑可以，不进产品

和「豆包」撞「豆」，是**寄生态**而不是**建品牌**：用户会一直拿你和豆包比，而你的卖点恰恰是「不靠大厂」。
另外「moe」在 ASR 语境里没有意义（MoE 是混合专家架构，你这两个模型都不是 MoE），别把它写进文案，会被懂行的人一眼看穿。

## 3. 命名架构：三段式，别混成一段

IDM 那种分包里，名字承担三件不同的事，混在一起就会得到一个「搜不到、记不住、说不清」的名字：

| 段 | 作用 | 要求 | 反例 |
|---|---|---|---|
| 品牌名 | 被搜索、被口口相传 | 短、独特、可注册、**唯一可搜** | listen anything |
| 品类词 | 让人 3 秒懂这是什么 | 直白、不用解释 | 「智能语音中枢」 |
| 定位句 | 说清凭什么选你 | 可现场演示 | 「AI 赋能」 |

你的定位句其实已经想清楚了，而且**是可演示的**，这比任何形容词都有力：

- 「拔掉网线，它还在写。」——断网演示，10 秒说服。
- 「录音不进云，文件在你盘里，卸载也还在。」——我们的存档本来就是 `meetings/` 下的明文 md，这条**现在就是真的**，不是承诺。
- 「留学生的课，一句都不能漏。」——这是你对「绝对可靠」的原话，比「高精度」具体。

这三句分别对应**离线 / 数据主权 / 场景可靠性**，正好是豆包会议给不了的三件事。这才是对标的落点：不是比功能，是比「谁的录音不出这台机器」。

## 4. 三个命名方向（都未做商标检索，不可直接对外）

| 方向 | 逻辑 | 例子 | 优点 | 风险 |
|---|---|---|---|---|
| **A 器物系** | 名字说「它是什么」，不说「它做什么」 | 磁带 / 录音笔 / 本子类隐喻 | 功能迭代不废名；器物天然带「物理、离线、自持」气质，与解绑大厂同源 | 好词大多被占，需造词 |
| **B 能力系** | 名字说「它能听什么」 | `earshot`（听力所及）、`all ears` | 语义直给，国际可读 | `earshot.com` 实测已注册；`All Ears` 有同名英语播客（正是留学人群） |
| **C 中文优先** | 中文名 + 拼音域 | 耳记 / 言迹 / 拾句 / 留声 | 国内搜索与口碑传播最省力 | 前三个已查出同名工具或产品，需重新筛 |

**我的倾向是 A**：器物名不描述功能，所以「以后从转写扩到别的」不用改名；而磁带 / 录音笔这一族，语义上就是「本地、可持有、不联网」，和你说的树莓派气质是同一件事。但这需要造一个能注册的短词，`tape` 族的好词也大多被占——**下一步应该先定方向，再批量 RDAP 筛 20 个候选，而不是先想名字**。

## 5. 待你拍板的两件事

1. **方向选 A / B / C**（或给一个你想到的词）。定了我批量筛域名 + 做 16px 小尺寸可辨性验证。
2. **改名要不要动数据目录**。现在会议存档在 `meetings/`、发现文件是 `web_live.json`。
   改名如果顺手把目录也改了，**历史会议会全部「消失」**（文件还在，程序找不到）。
   建议：品牌名改，**目录名永久冻结**，用 `config` 里的 `archive_dir` 指过去。

未验证项（不要当结论）：`.app` 域名可用性、任何商标检索（CNIPA / USPTO 都没查）、zh-14M 在真实会议音频上的实际错字率。

## 6. 决定：offlisten（2026-11-12 实测）

### 6.1 域名：可用

| 域 | 结论 | 依据 |
|---|---|---|
| `offlisten.com` | **未注册，可注册** | Verisign RDAP `HTTP 404`（.com 权威库） |
| `offlisten.net` | **未注册** | 同上 |
| `offlisten.cn` / `.io` | **未验证** | Verisign 不辖这两个 TLD，查询返回 404 无意义 |

**更正上一版文档的一处措辞**：`offtalk.com` RDAP 返回 200 只证明「已被注册」，**不等于「已有产品在用」**。
实际截图显示它挂在 HugeDomains 待售，标价 **$6,095**。已注册 ≠ 有主在用 ≠ 买不到，这是三件事，之前混成一件了。

### 6.2 唯一实风险：Offlist 近似

`offlisten` 没有同名产品，但有一个**只差两个字母**的近邻 `Offlist`，且占了三个位：

| 占用 | 是什么 |
|---|---|
| `offlist.today` | AI 规划 / 清单工具 |
| Product Hunt（2026-04 上线） | **offline、privacy-first、无账号无云**的待办+笔记 app |
| `offlist.co` | 商业地产多语言挂牌 |

风险分两层，要分开看：

- **商标**：品类不同（转写 vs 待办/地产），冲突风险低。
- **搜索 / 拼写**：这是真实成本。用户少打 `en` 两个字母就落到别人站；`off-` 前缀的「离线 + 隐私」语义场也已经被它占了。
- **缓解**：不靠 `off` 前缀自带解释，靠 tagline 和中文名承担解释；`offlist` 系列只当投放词，不当品牌词。

### 6.3 名字与图标必须对齐（这条是真问题）

你给的组合是「icon 像磁带 + 名字 offlisten」。名字里是 **listen（被动听）**，产品交付的是 **record + 可读文本（主动产出）**。
只喊 listen，新用户第一反应会是「播放器 / 助听 / 语音助手」，而不是「把课录成能读的字」。

- **图标语义没问题**：框 + 黄条 = 正在被写下的那一句，与实现一致（`facts_markdown` 里 `trans` 段加「译 」前缀也是同一套语义）。
- **但 tagline 必须把 listen 补成 record**：
  - `Offlisten — record anything. Offline.`
  - 中文：`离线听，也离线记。`

### 6.4 中文名：不能省

`offlisten` 对留学生的英文界面够用，对中文普通用户是「一串英文字母」。而你要的传播恰恰靠口传。
- 音译系无解（奥夫listen 不可口传）。
- 语义系（留声 / 拾音 / 听录）前两个已查出同名占用，需重新筛。
- **建议**：暂时不硬造中文品牌名，完整叫法用 **「Offlisten · 离线转写」**，让种子用户自然长出简称，再造词才准。

### 6.5 已落地

`manifest.json` / `popup.html` / `popup.js` 的显示名已改为 Offlisten（**v0.2.0**），真机回归 **10/10**，扩展 ID 保持 `hbfbckcf…` 未变（ID 由加载路径派生，与 name 无关）。
**只改显示名，没动 `meetings/` 与 `web_live.json`** —— 历史会议不受影响。

### 6.6 还没做

1. 注册 `offlisten.com` + `.net`（`.com` 为主、`.net` 防钓鱼；面向国内再补 `.cn`，备案需要）。
2. 商标检索 CNIPA 第 9 类（软件）/ 第 42 类（SaaS）—— **这条我没查，别当已通过**。
3. 改名会动到用户数据路径（会议存档在 `meetings/`、发现文件是 `web_live.json`）。**保留目录名或写迁移脚本，必须单独决定**——
   否则历史会议在用户眼里会「消失」。

## 7. 域名成本与中文名（2026-11-12）

### 7.1 拿下 offlisten.com 要多少钱

价源：`tld-list.com/tld/com`（实测抓取，标注「1 小时前更新」），全市场区间 **$3.80（促销）～$60.49（高位）**。

| 项 | 实测价（USD） | 说明 |
|---|---|---|
| 首年注册 | **$7.90 – $10.46** | 主流注册商，含 ICANN 费；$7.90 是优惠码价 |
| 续费 | **约 $9 – $15 / 年** | 首年便宜、续费贵的注册商要避开 |
| 10 年一次性 | **约 $100 – $140** | 合人民币 **约 700 – 1000 元** |
| WHOIS 隐私 | **$0** | 主流境外注册商免费 |
| 国内注册商参考 | 首年 ¥55–75 / 续费 ¥85–95 | 需实名认证（个人可） |

**结论：百元级/年，10 年不到一千块，不是财力问题。** 真正的成本不是钱，是决定拿它做什么。

### 7.2 不建站也成立，但域名的作用要搞清

- 你的判断对：Cloudflare Pages / GitHub Pages 免费够用，域名 301 过去就行。
- **备案**：只有用**中国大陆服务器或 CDN** 才需要 ICP。解析到境外免费托管**不需要备案**，代价是国内访问可能慢。这条常被搞混，写清。
- 域名的真实价值不是「有个网站」，是**唯一不依赖平台账号的资产**——账号会被限流、封号、改算法，域名不会。你铺 YouTube + X + B站 + 小红书，正需要这个锚点。
- **零成本等价动作**：先把四个平台的 handle 全占成 `offlisten`。这一步免费，且比域名更早决定搜索资产能不能攒起来。
- **口径必须统一**：所有平台**显示名**用「录匣 Offlisten」，**handle 只用拉丁字母** `offlisten`。中英混进同一个 handle 会把搜索资产切碎——这也是「双语单独设计」的执行方式：**中文负责被记住，英文负责被输入**。

### 7.3 中文名：录匣

- **不是翻译**。`Offlisten` = 状态 + 动作（离线地听）；`录匣` = 器物 + 结果（装录音的匣子）。两个名字各自独立成立，合起来才覆盖完整语义。
- **和图标天然对齐**：匣 = 方盒，正是磁带壳；图标里那个框就是匣，框内黄条是匣里正在被写下的那一句。这次名字、图标、语义三者一致，不是硬凑。
- **搜索现状**：`"录匣"` 搜不到任何同名产品——也搜不到任何东西。它是**造词**，零搜索量，这是要付的代价，不是捡来的红利。
- **已排除**：`声盒`（台湾源壹「智慧声盒 SoundBox」已是产品线）、`录本`（市面已有「智能录音本」「语音记录本」多款，会被淹没）、`留声` / `拾音`（此前已查出同名占用）。
- **两条风险**：① `匣`(xiá) 是中等生僻字，视频里必须念一次，否则用户打不出来；② 前 3 个月搜「录匣」什么都搜不到（好处是也没有竞品）。

### 7.4 已落地 v0.2.1

`manifest name` = `Offlisten 录匣 · 离线转写`；popup h1 = `录匣 Offlisten` + tagline「离线听，也离线记。拔掉网线它还在写。」；复制头 = `# 录匣 Offlisten 事实源`。
真机回归 **10/10、0 FAIL**，扩展 ID 仍为 `hbfbckcf…`，未改 `meetings/` 与 `web_live.json`。
